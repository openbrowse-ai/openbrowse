**Sync the agent's global memory across your Chrome profiles.** Point each profile at the same folder and everything the agent has learned about you — `memory/**` — stays in step between them. Put that folder in Dropbox, iCloud Drive, Drive, or a git repo and it follows you across machines too. There is no server and no account: the folder is the sync channel.

The folder is a genuine markdown vault, not an export format. `memory/**` mirrors exactly what Settings → Memory shows, so you can open it in Obsidian, grep it, hand-edit a note (edits are picked up), or `git log` how your agent's understanding of you changed. Sync metadata hides in a `.openbrowse/` dotfolder, and the path validator refuses dotted segments, so metadata can never be mistaken for a note.

- **Three-way merge, not last-writer-clobbers-everything.** Each profile keeps a baseline of `path → sha256` as of its last sync, which is what distinguishes "I created this note" from "the other profile deleted it." Different notes edited in different profiles merge cleanly; only the same note edited in both is a conflict.
- **Conflicts keep both versions.** The newer note wins by its `updated` frontmatter date, falling back to file mtime — frontmatter first because backups and cloud clients disturb mtime while leaving the note's own record of its last real change intact. The losing copy is archived under `.openbrowse/conflicts/` and listed in Settings → Memory with Restore and Dismiss. It is deliberately kept *outside* `memory/**`: a `garry-tan (conflict).md` living in the tree would get indexed, give the agent two notes for one entity, and make the bare-basename `[[garry-tan]]` link ambiguous — which `memoryStore.graph` faithfully fans out to both, corrupting the graph.
- **Deletes propagate, but an edit always beats a concurrent delete.** Deleting a note in one profile removes it in the others via a per-path tombstone. If you edited a note in one profile while deleting it in another, the edit wins and the note returns — losing a note you just wrote is worse than seeing one you deleted come back, and the restore is reported rather than silent. A note that merely *vanished* from the folder with no tombstone is restored, not treated as a delete, so a half-synced cloud folder can't cascade into erasing your memory.
- **First sync never deletes.** With no baseline every path is new, so linking an already-populated folder unions the two trees. Stopping sync unlinks and deletes nothing, anywhere.
- **Sync is a checkpoint, and the UI is honest about why.** Chrome does not reliably keep folder permission across browser sessions, and it can only be restored by a click — which a background service worker cannot produce ([crbug.com/1359786](https://crbug.com/1359786)). So sync runs when an OpenBrowse surface is open: on open, on refocus, after an agent run, on a debounced memory write, or from **Sync now**. Those automatic passes skip silently when permission has lapsed and never nag; Settings shows a routine "Reconnect the folder" instead of an error.
- **The folder is treated as untrusted input**, because it may be shared, cloud-synced, or checked into a repo. Every incoming path is validated segment by segment — no traversal, no absolute paths, no backslashes, no dotfiles, no control characters — then required to resolve inside global `memory/**` as markdown, and capped at 1,000 files and 1 MB each, with anything refused reported in the UI rather than swallowed. Sync uses SHA-256 rather than the index's 32-bit FNV-1a hash, because a collision here decides what gets overwritten or deleted rather than merely marking a cache stale.

Space-scoped memory (`spaces/<spaceId>/memory/**`) does **not** sync: `Space.id` is a per-profile UUID with no portable identity, and matching spaces by name would silently merge two unrelated projects that happen to share one. Explicit space pairing is the follow-up.

Also corrects `docs/memory.mdx`, which still documented the four memory tools removed in 0.15.0 (`saveMemory`, `recallMemory`, `updateMemory`, `deleteMemory`), claimed memories live in "extension storage" rather than as OPFS files, and said editing a memory requires approval when only Delete does.
